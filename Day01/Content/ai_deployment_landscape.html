Pay-as-you-go vs reserved GPU

🧾 Pay-as-you-go
e.g. Bedrock on-demand · Azure pay-as-you-go · Vertex pay-as-you-go
  • + Start in minutes, zero idle cost
  • + Scales for you; latest frontier models
  • + Cost = usage → easy to chargeback
  • − Cost grows linearly with traffic
  • − Rate limits / throttling at peak
  • − Latency and model versions not in your hands
Best when: pilots, spiky or unknown traffic, small teams.
🖥️ Reserved GPU / provisioned
e.g. GPU VM + vLLM · Bedrock Provisioned Throughput · Azure PTU · on-prem GPUs
  • + Flat, predictable bill
  • + Cheaper per token if kept busy
  • + Guaranteed capacity, steady latency
  • − Idle GPU = money burning
  • − You size, patch, monitor (self-host)
  • − Commitment (1–6 months) on provisioned plans
Best when: steady, high, predictable volume; strict latency or residency.

So when DO you go for a GPU?

🖥️ Go for GPU when several of these are true
  • Steady, high volume — GPUs stay busy (50%+) most of the day, every day
  • Data can't leave — regulator or client demands your own infrastructure
  • Guaranteed speed — no throttling allowed (voice, call-centre, real-time)
  • Custom open model — fine-tuned, quantised, or air-gapped
  • Someone owns it — GPU ops skills and on-call exist
🧾 Stay pay-as-you-go when
  • Pilot or unknown demand — you can't predict the load yet
  • Spiky traffic — busy 9–11 am, idle at night (idle GPU still bills)
  • Frontier quality needed — not available as open weights
  • Small team — no MLOps, no on-call
  • Short deadline — weeks, not months
The usual answer is a path, not a switch: start pay-as-you-go → measure 1–2 months of real traffic → move only the steady, high-volume workload to provisioned capacity or GPUs → keep the spiky and hard tasks on the API.
Hidden costs the bill hides: idle hours, the spare GPU, people time, patching, and re-testing every time a better model arrives.

Proprietary vs open-weight — the ADR in one screen

🔒 Proprietary (API)
Claude · GPT · Gemini · Amazon Nova
  • + Top quality, tool-use, long context
  • + No GPUs to run; vendor patches & scales
  • − Data goes to the provider's cloud (region-pinned)
  • − Price & versions set by vendor; deprecations
  • − No weights → no deep customisation
🔓 Open-weight
Llama · Mistral · Qwen · DeepSeek · Gemma
  • + Run anywhere — even air-gapped
  • + Fine-tune, quantise, full control of cost curve
  • + Also available per-token on Bedrock / Vertex / Foundry
  • − If self-hosted: GPUs + MLOps + security are yours
  • − Check licence terms (commercial use, size limits)
  • − Frontier gap on hard reasoning / agents (shrinking)

"Open-weight" ≠ "open-source": you get the model files, not always the training data or an OSI licence. Good enough for ADRs — but read the licence.
