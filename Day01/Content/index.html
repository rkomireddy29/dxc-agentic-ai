Module 1 · BASIC

How we got from autocomplete to agents

Click Next step to walk the evolution.

Completion
Predict the next word. Give it text, it continues the text. Powerful, but no instructions, no memory.
Chat
Follow instructions. Tuned to answer questions in a conversation. Still only knows its training data.
+ Retrieval
Read your documents (RAG). We fetch relevant text and put it in the prompt. Now it can answer about your policies.
+ Tools
Call functions. The model asks us to run a tool (e.g. get_ticket) and uses the result.
Reasoning
Think before answering. Models spend extra "thinking" tokens to plan multi-step problems.
Agents
Loop until done. Reason → act (tool) → observe → repeat — the model decides the next step. This is AskIT.

🧪 Lab C · 40 min

Structured ticket extraction

What we doTurn messy ticket text into clean, validated fields (category, priority, user, summary, sentiment) and check the result against the human label.
WhyAgents need data, not prose. Structured output plus validation makes results reliable.
Outcome / learningReliable structured output from an LLM, and a feel for where it agrees or disagrees with a human.
HowDefine the Ticket schema (TODO-4) → force the model to answer through a tool call and validate it (TODO-5) → run it on 5 real tickets.
  1. Same folder, same (.venv). Open lab01b_extract.py and search for TODO-4.
  2. TODO-4: finish the Ticket schema (5 fields with rules).
  3. TODO-5: make the model answer through a tool call, then validate it against the schema.
  4. Run: python lab01b_extract.py. You should see 5 tickets, each marked OK or DIFF (DIFF = the model disagrees with the human label — who is right?).
  5. Check: pytest → all 5 pass.
  6. Ignore the TODO-6 note in the file and the “Langfuse” message at the end of the run — that is for a later session.
  7. stretch Same ticket 5× at temperature 0 vs 1 — how many fields change?
Stuck? ValidationError → check the allowed values in your schema · Throttling → wait 30 s and re-run.
